# Polygon agent facilitator

The user selected Polygon PoS mainnet (137 / `eip155:137`). MetaMask device acceptance will be performed later by the user. The code accepting Polygon is separate from proof of a live purchase.

Use the manifest generated by EC's `packages/agent-commerce/scripts/polygon-deployment.mjs manifest`. The same manifest is used by both repositories. It pins the actual deployed Gate, Adapter, Validator, official Manager/account/enforcers, JPYC/native USDC proxies and implementations, and Uniswap router/factory. Both tokens require implementation pins. Circle USDC uses its custom proxy slot, not the EIP-1967 default.

Set `AGENT_COMMERCE_ENABLED=true`, `AGENT_DEPLOYMENT_MANIFEST`, `AGENT_RPC_URL`, `AGENT_RELAYER_PRIVATE_KEY`, `AGENT_JOURNAL_PATH`, `AGENT_EC_ORIGIN`, `AGENT_EC_KEY_ID`, `AGENT_EC_HMAC_SECRET`, and `FACILITATOR_HMAC_KEYS`. The public-chain relayer key must match the shared manifest and must differ from the legacy EIP-3009 key. Fund its gas with POL; keep the SQLite journal on persistent storage. Node 22.14+ is required. Worker agent execution remains disabled.

Use the complete [environment template](./facilitator.env.example). The host also initializes the legacy lane: set `NODE_ENV=production`, `ENABLED_NETWORKS=eip155:137`, `CORS_ORIGINS` to the exact EC origin, `RPC_URLS_137` and `RELAYER_PRIVATE_KEY`. Legacy network settings do not enable the agent lane. Runtime agent manifests are restricted to Polygon; Sepolia and local development are available only with `NODE_ENV=test`. RPC and EC URLs require HTTPS, except explicit loopback HTTP in tests. EC-origin paths, credentials and short HMAC secrets are rejected before network access.

Build and run from the repository root:

```sh
pnpm install --frozen-lockfile
pnpm --filter @jpyc-x402/server... build
node --env-file=/secure/facilitator.env apps/server/dist/main.js
# Or build the image locally; this does not deploy it:
docker build -f apps/server/Dockerfile -t jpyc-agent-facilitator:ethtokyo2026 .
```

`vendor/jpyc-ec-agent-commerce-0.1.2.tgz` is required in both Docker install stages. The image excludes local env files, SQLite state and node_modules. Mount the completed manifest read-only and `/persistent` as a writable durable volume owned by the runtime `node` user (uid 1000). Put it behind TLS. Run exactly one instance for this relayer/journal and disable automatic horizontal scaling. Do not reuse the agent key in a separate script, Node host or Worker; its nonce allocator must have one owner. The default `/health` endpoint checks process liveness, not World, EC or Polygon acceptance.

On restart, retain the **same key, manifest and journal including SQLite WAL state**. The five-second reconciliation loop resumes stored transactions. Do not delete the journal, reset nonce counters, re-sign an unknown purchase, or create a replacement order to recover a timeout. Keep a SQLite-consistent backup (stop the process before copying the database and its sidecar files, or use SQLite's backup API). If the disk/key is unavailable, stop the agent lane and inspect canonical chain receipts before any resumption. A changed token implementation/code pin stops execution and requires reviewed configuration, not disabling verification.

The default legacy RPC configuration does not configure this agent path. Use a validated Polygon HTTPS endpoint. EC's read-only preflight compares two RPC providers, implementation slots and 100/1,000/10,000 JPYC exact-output quotes. Those quotes must be refreshed at purchase time.

After device permission acceptance and the EC integration are ready, start with one 100 JPYC purchase, then the user-approved 1,000 JPYC × 10 sequence. Match both PurchasePaid and JPYC Transfer to the EC order. Record actual USDC input, gas, confirmation time and recovery. A lost broadcast response must recover the same stored raw transaction; unknown status is never proof of nonpayment.

The business budget OR an exact-order approval from the registered person remains unchanged, including period-budget overrun. Expiry, revocation, tampering and signature/approval replay stay non-overridable. This document does not claim deployment, wallet acceptance, World/Intercepta acceptance or live purchases.
